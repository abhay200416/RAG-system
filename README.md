# RAG Assistant

A retrieval-augmented assistant with a FastAPI backend and Streamlit frontend.
Docker Compose starts the API, UI, PostgreSQL with pgvector, and Redis.

## Requirements

- Docker Desktop with Docker Compose
- A Google AI API key (used for document and query embeddings)
- A random API authentication key

Groq is optional and can be configured as an alternate answer-generation
provider.

## Configure

In PowerShell, create your local environment file:

```powershell
Copy-Item .env.example .env
```

Edit `.env` and replace these placeholders:

- `RAG_GOOGLE_API_KEY`: your Google AI API key
- `RAG_API_AUTH_KEY`: a long, random secret
- `POSTGRES_PASSWORD`: a random hexadecimal password

Use hexadecimal characters for `POSTGRES_PASSWORD` so it can safely be placed
in the PostgreSQL connection URL generated by Compose. Keep `.env` private; it
is excluded from the Docker build and Git.

`RAG_DATABASE_URL` is for running the app directly on your computer. Compose
overrides it inside the API container to connect to the `db` service. Set
`RAG_API_BASE_URL` only if you change the API address used outside Compose; the
frontend container is configured to use `http://api:8000`.

## Start the Docker deployment

From the project directory:

```powershell
docker compose up --build -d
docker compose ps
```

Open:

- Streamlit UI: <http://localhost:8501>
- API health: <http://localhost:8000/health>
- API documentation: <http://localhost:8000/docs>

The UI reads `RAG_API_AUTH_KEY` from `.env`; there is no key field in the
frontend. The API requires that key for protected routes.

The first document upload initializes the PGVector tables. Until then,
`/health/ready` can report that vector storage is not initialized even though
the API is running. Docker health checks use the liveness endpoint.

## Use the application

1. In **Ingest**, add text, upload a PDF/TXT/Markdown/HTML file, or submit an
   allow-listed HTTPS URL.
2. In **Search**, run hybrid retrieval and view reranked source chunks.
3. In **Chat**, ask a question and view the generated answer with its sources.

URL ingestion is disabled unless `RAG_INGEST_ALLOWED_HOSTS` contains a JSON
array of exact trusted hostnames, for example:

```dotenv
RAG_INGEST_ALLOWED_HOSTS=["docs.example.com"]
```

The URL loader accepts HTTPS only, does not follow redirects, requires public
DNS results, and enforces the configured upload-size limit.

The default PostgreSQL image includes pgvector, not ParadeDB. Hybrid search
therefore uses PostgreSQL full-text ranking together with vector search. To use
BM25, install ParadeDB `pg_search` on the database server and create its index
with `CREATE_BM25_INDEX()` from `rag.retrieval.retrieval`.

## Logs and shutdown

Follow service logs:

```powershell
docker compose logs -f api
docker compose logs -f frontend
docker compose logs -f db
```

Stop the services and preserve the database:

```powershell
docker compose down
```

To also permanently delete the PostgreSQL volume and its stored documents:

```powershell
docker compose down -v
```

## Run without Docker

For a local Python run, first provide a reachable PostgreSQL server with
pgvector and set `RAG_DATABASE_URL` in `.env`. Then run:

```powershell
uv sync
uv run rag-api
```

In a second terminal:

```powershell
uv run streamlit run src/fronend/streamlit.py
```

## Troubleshooting

- **API authentication is not configured:** verify `RAG_API_AUTH_KEY` is set
  in `.env`, then restart the API and frontend containers.
- **Cannot connect to PostgreSQL:** check `docker compose ps` and
  `docker compose logs db`. The API uses the Compose database hostname
  internally; do not use `localhost` for the container's database URL.
- **Upload or embedding fails:** inspect `docker compose logs api`. Gemini
  Embedding 2 creates one vector per chunk, so large files may take longer.
- **Request returns HTTP 500:** note the request ID shown by the UI and inspect
  the API logs for the matching traceback.
- **Port is already in use:** change `RAG_PORT` or `POSTGRES_PORT` in `.env`,
  then restart Compose.

## API endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/health` | Public liveness check |
| `GET` | `/health/ready` | PostgreSQL/pgvector readiness and active search mode |
| `POST` | `/ingest` | Ingest text |
| `POST` | `/ingest/file` | Ingest a supported document upload |
| `POST` | `/ingest/url` | Ingest an allow-listed HTTPS page |
| `POST` | `/search` | Hybrid retrieval and reranking |
| `POST` | `/query` | Retrieval, reranking, and answer generation |
